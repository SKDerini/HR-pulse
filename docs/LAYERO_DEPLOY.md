# Развертывание на Layero

## 1. Подготовьте базу

1. Войдите в `app.layero.ru`.
2. Создайте PostgreSQL в разделе **«Базы данных»**.
3. Включите Data API и подключите базу к будущему проекту.
4. Откройте SQL-редактор и целиком выполните `database/001_hr_stroyakov_v2.sql`.

Если база версии 2.0 уже развернута и содержит рабочие данные, **не очищайте ее**. Выполните только `database/002_offers_v2_1.sql`: миграция добавит индексы, проверки и сущности офферов без изменения прежних записей.

Если раздела баз нет, доступ к пилоту нужно запросить через чат в правом нижнем углу панели Layero.

## 2. Создайте первого пользователя

Создайте пользователя через Layero Auth. Пример запроса:

```bash
curl -X POST "https://data.layero.ru/SLUG_БАЗЫ/auth/v1/signup" \
  -H "apikey: pk_live_ВАШ_ПУБЛИЧНЫЙ_КЛЮЧ" \
  -H "content-type: application/json" \
  -d '{"email":"admin@example.ru","password":"НАДЕЖНЫЙ_ПАРОЛЬ"}'
```

После регистрации вернитесь в SQL-редактор и назначьте роль:

```sql
select app.set_user_role(
  'admin@example.ru',
  'HRD',
  '',
  true,
  'Первый администратор'
);
```

В версии 2.1 модуль «Настройки» временно неактивен. Остальных пользователей назначайте в SQL-редакторе той же функцией `app.set_user_role`, меняя email, роль и при необходимости Employee ID.

Для приема опросов из внешней формы задайте отдельный длинный токен:

```sql
select app.set_ingest_token(
  'Основная форма опросов',
  'СЛУЧАЙНАЯ_СТРОКА_НЕ_КОРОЧЕ_24_СИМВОЛОВ',
  true
);
```

Форма должна вызывать `POST /rest/v1/rpc/hr_submit_survey` и передавать `p_token` и `p_payload`. Функция принимает только поля опроса и не открывает таблицы анонимному пользователю.

## 3. Подключите веб-приложение к Data API

Создайте локальный `.env.local` по образцу `.env.example`:

```dotenv
VITE_LAYERO_DATA_URL=https://data.layero.ru/SLUG_БАЗЫ
VITE_LAYERO_DATA_KEY=pk_live_ВАШ_ПУБЛИЧНЫЙ_КЛЮЧ
```

Секретный ключ `sk_live_…` во фронтенд не добавляйте. Для приложения нужен только публичный ключ `pk_live_…`.

Локальный `localhost` разрешен Data API автоматически. Домен подключенного проекта Layero добавляется в разрешенные источники также автоматически.

Проверьте рабочий режим:

```bash
npm install
npm run dev
```

Должна появиться форма входа, а после авторизации — зеленый статус **«Layero PostgreSQL подключена»**.

## 4. Разверните проект

Требуется Node.js 20 или новее; проект фиксирует Node.js 22 в `.nvmrc`.

```bash
npx layero@latest init
npx layero@latest login
npx layero@latest deploy
```

CLI определит Vite, выполнит сборку и покажет точный адрес проекта в зоне `layero.app`.

Важно: для проекта без подключенного GitHub обычный CLI-деплой сразу обновляет рабочий адрес. Для изолированных preview-окружений подключите GitHub и используйте отдельные ветки.

## 5. Перенесите данные

Сначала подготовьте JSON по инструкции `MIGRATION_FROM_GOOGLE.md`. После входа под HRD нажмите **«База данных» → «Загрузить JSON»**. Записи загружаются пакетами по 500 и проходят серверную проверку роли.

## Проверка после развертывания

1. Активны HR Pulse, Реестр офферов и Табель; остальные девять блоков видны серыми и не открываются.
2. Руководитель видит только дерево подчиненных.
3. Табельщик видит только назначенную область.
4. Месяц табеля формируется и массово сохраняется.
5. Файл СКУД загружается в выбранный месяц.
6. Итоговый Excel скачивается с буквами и цветами.
7. JSON-резервная копия формируется из рабочего интерфейса.
8. HR/HRD создает оффер, меняет сумму и сохраняет новую версию мотивации; прежняя версия остается в истории.
